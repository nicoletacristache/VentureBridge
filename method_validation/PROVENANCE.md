# Benchmark Provenance and Scope

This is the central source and interpretation note for the released method-validation assets. Other documentation links here rather than repeating the source discussion.

## Original source metadata

The original frozen dataset identifies itself as `venturebridge-synthetic-method-validation-v1.8.0`. Its configuration and freeze manifest set `synthetic_only=true`. Its data card states that the trajectories, audit responses, annotation rounds, and adjudication records are constructed by deterministic rules and seeded random processes. The dataset version and source-status fields in the archived files are preserved without relabeling.

The original data card is consolidated in this note below. The archive retains the original machine-readable configuration, summary, and freeze manifest. The data-generation program and three annotation-prompt templates are not published in the dataset archive. Their exclusion does not change the source or meaning of the retained records.

## Measurement design

The measurement runner evaluates a known-reference benchmark and requires calibration reference abilities and nuisance-facet truths. Its full method is a calibrated penalized ordinal/MAP approximation, not a fitted run of the Stan model. The Oracle reference uses privileged information and is not a deployable empirical baseline. Expert ordinal ratings alone do not supply known latent abilities.

The nine measurement methods consist of the full method, seven comparison methods, and the Oracle reference. Static, unanchored, and simplified variants share the calibration framework and are not separate external algorithm reproductions.

The ECD evaluation compares a Chinese keyword-and-structure rule encoder with the application's structured LLM encoder on 300 matched items. Terminal LLM failures use the same-item rule prediction as a fallback. Reference labels are kept separate from encoder input.

## Release integrity

The benchmark archive retains 36 original non-cache data assets. It excludes the original data card (consolidated below), the generation program, and three annotation-prompt templates. The historical freeze manifest describes the larger original set; `source_manifest.json` defines and verifies the published subset. The reference-output archive retains nine final prediction/configuration assets. The 22 result files are unchanged. `source_manifest.json` records original-file hashes, and `release_checksums.json` records hashes of the published files.

Code-level edits, if made for packaging or documentation, are listed in this note. The numerical procedures, input records, saved predictions, and result values are not altered by this release. The inference code uses credentials from the runtime environment; no real credential is included.

## Excluded materials

Application-validation records, application databases, developer conversations, execution sessions, development predictions, caches, credentials, paper drafts, and unrelated intermediate files are excluded. No classroom-effect or verified human-expert provenance claim is established by this method-validation release.

## Packaging changes to source code

Only the top-level explanatory docstrings in `run_measurement_validation.py`, `score_ecd_audit.py`, `evaluate_ecd_audit.py` were replaced with short descriptions linking to this note. Their imports, constants, executable statements, function bodies, and numerical procedures remain unchanged.

```markdown
# 合成方法验证数据卡

## 1. 数据集身份与状态

- 数据集版本：`venturebridge-synthetic-method-validation-v1.8.0`
- 状态：`FROZEN`（2026-10-31 起不再改变记录）
- 生成日期：2026-10-30
- 主随机种子：`20261030`
- 蓝图库：`venturebridge/data/blueprints.json`
- 蓝图库版本：`2026-10-30.core-v2`
- 主测试单位：一条包含 16 个事件的完整合成学习者轨迹
- 最终测试单位数：严格为 300 条轨迹
- ECD 审计版本：`ecd-audit-salted-holdout-v2`

本数据集全部由冻结规则和伪随机生成过程构造。所有学习者代号、画像层、回答、评分、能力、状态及外部准则均为合成数据，不对应真实个人、学校、企业、课程、专家或观察记录。数据不能用于估计真实学生分布、真实教学效果或现实创业成功概率。

## 2. 验证用途

数据服务于以下离线方法验证：

1. 检验共同锚能否在画像分支和连续状态不同的轨迹之间建立共同量尺；
2. 检验动态多面方法能否从序数过程证据中恢复合成的五维能力及变化；
3. 比较完整方法与规则分、原始量规分、最终状态、线性锚定、静态模型、无锚动态模型和简化动态模型；
4. 检查事件蓝图、表面形式、可见状态、评分者漂移及评分版本效应的恢复；
5. 用独立的 300 条平衡文本审计集评价辅助 0—4 级 ECD 编码。

数据不包含真实部署、真实参与者持续使用、课堂干预或学习结果，因此不得据此声称应用效果。

## 3. 数据来源与构建方式

### 3.1 结构来源

事件名称、目标维度、冻结锚文本、表面形式、状态版本和规则行动来自当前 `core-v2` 蓝图库。六个主线蓝图和五个锚家族均被使用。锚家族包括：

- `anchor_opportunity`
- `anchor_resource`
- `anchor_team`
- `anchor_adaptation`
- `anchor_responsibility`

### 3.2 合成内容来源

- 轨迹能力、状态、评分噪声和各测量面：规则生成；
- 主线事件表述：根据蓝图标题、合成画像和可见状态模板生成；
- 锚事件表述：直接使用版本化蓝图库中的冻结文本；
- 开放回答：按冻结五维行为等级语句、规则行动和案例状态组合生成；
- ECD 审计回答：按维度、等级和常见/边界/噪声条件模板生成；
- 三轮标注：以冻结构造等级和案例类型为中心，使用相互隔离的种子与预设误差模型生成三轮合成独立判断；轮次之间不互读，也不读取待评价方法预测；
- 裁决：只依据冻结量规和构造证据，不读取任何待评价方法的预测。

所有合成记录均设置 `synthetic=1`，轨迹包另含明确的合成声明。

## 4. 样本规模与隔离

| split | 完整轨迹 | 每条事件数 | 锚/主线 | 事件行 | 事件×证据维度行 |
| --- | ---: | ---: | ---: | ---: | ---: |
| calibration | 600 | 16 | 5/11 | 9,600 | 28,800 |
| validation | 150 | 16 | 5/11 | 2,400 | 7,200 |
| test | 300 | 16 | 5/11 | 4,800 | 14,400 |
| 合计 | 1,050 | — | — | 16,800 | 50,400 |

每个事件—证据维有 3 条交叉评分，故评分长表共 151,200 行；这三条评分不改变 300 条测试轨迹这一主测试单位数。

三组使用不同的学习者 ID、轨迹 ID 和稳定随机流。任何学习者的事件、评分、能力真值或外部准则只属于一个 split。正式方法应仅用 `calibration` 拟合，用 `validation` 选择结构或阈值，最终 `test` 真值只用于一次性评价。

ECD 编码另有物理隔离的 60 条提示/接口开发材料与 300 条正式留出材料。开发集按维度边际各 12 条、按等级边际各 12 条，含 35 条常见、15 条边界和 10 条噪声案例；因 60 不能被 25 个“维度×等级”单元整除，各交叉格含 2 或 3 条。正式集按五维×五档×每格 12 条严格平衡，共 175 条常见、75 条边界和 50 条噪声案例。两组分别使用 `ecd-prompt-development-2026-10-30-v1` 与 `ecd-final-holdout-2026-10-30-v1` 盐值作独立确定性选择；ID、材料编号、四字段回答表面和去除材料编号后的实质完整输入均不重合。开发材料不进入正式指标。

## 5. 轨迹构成与平衡

- 每条轨迹有 4 周、每周 4 个事件，共 16 个事件；
- 锚位置固定为第 3、6、9、12、15 轮；
- 每名合成学习者恰好遇到五个不同锚家族，各一次；
- 锚家族顺序采用五种循环顺序，在每个 split 内对位置平衡；
- 每个锚家族的形式按 exact:surface-A:surface-B 约 2:1:1 分配；
- 每个家族的三个状态版本均衡；
- 在 calibration 和 test 中，形式×状态组合精确成比例平衡；validation 因 150 不能被 12 整除，每个单元相对其比例配额最多偏离 1（两个单元之间的计数范围可为 2）；
- 四种纯合成画像层循环等量分配，不使用 MBTI，也不对应真实人口群体；
- 主线蓝图在每条轨迹内先覆盖六个蓝图再重复；主线路径挑战由可观察的“画像层×蓝图”固定单元效应和小幅事件噪声组成，使未经校准的原始均分混入分支难度，同时避免使用不可观察的真能力决定该效应。
- `core-v2` 每个蓝图原有两个维度仍是主目标维；理想合成目标条件另为每个蓝图预设一个内容适用的次级证据维，使每事件恰有三个可评分维度。该映射只属于验证数据配置，不修改生产蓝图库；主、次级证据对九种方法完全相同，并在长表中以 `evidence_role` 标记。

## 6. 能力与测量面生成

五个维度为：

1. `opportunity_framing`
2. `evidence_falsifiability`
3. `resource_finance`
4. `adaptive_action`
5. `stakeholder_ethics`

初始能力由一个共同因子和维度特异因子生成，并加入很小的画像层偏移。能力按事件发生轻度平均增长、个体增长差异和随机创新。序数证据由以下已保存真值共同决定：

```text
构造证据 = 当期能力
           - 蓝图难度
           - 表面形式效应
           - 可见状态效应
           - 个性化路径挑战项
           + 响应噪声
```

构造证据再通过四个冻结阈值映射为 0—4 级参考证据。独立评分在构造证据上继续减去评分者严厉度和版本效应并加入评分噪声。六名合成评分者在四个评分 occasion 上发生方向不同的小幅漂移；两个评分版本在各周和评分者之间交叉，避免版本与时间完全混淆。

每个事件对两个生产主目标维及一个冻结次级证据维生成评分，其他两个维度不被填成零。原两个主维仍单独决定规则行动和状态转移；次级维在行动抽取之后用独立稳定随机流生成，不反向改变该事件的规则行动。每个事件—维度有三条交叉评分；主评分始终存在，第二、三评分含少量预设 MAR 缺失并保留缺失行。

最终冻结 DGP 将个体增长标准差固定为 0.028、逐事件能力创新标准差固定为 0.018、构造响应噪声固定为 0.27、评分噪声固定为 0.21、原始量规分噪声固定为 0.34；画像层×蓝图路径挑战范围为 ±0.70 logit。其余阈值、状态系数、评分者漂移、版本效应、样本结构和随机种子均由 `generation_config.json` 冻结。这组参数表示信号相对清晰、路径差异可观察且足以考验多面校准的理想目标条件，不代表真实课程中的经验分布。

## 7. ECD 审计集与参考答案

`ecd_prompt_development_items.csv` 含 60 条仅用于冻结前检查提示接口、JSON 结构与逐字引文约束的合成材料，不进入性能比较。`ecd_audit_items.csv` 含另一套 300 条未用于提示调试的正式合成文本，按五维×五档×每格 12 条严格平衡。每个正式单元含 7 条常见、3 条边界、2 条带口语或省略噪声的案例。回答按生产评分接口拆成 `decision_text`、`rationale_text`、`information_requests` 和 `revision_text` 四个字段，并保留 `response_text` 作为可读拼接。边界模板覆盖“使用高阶量规术语但明确拒绝相应行动或更新”的冲突证据；其中 0 档边界还逐字呈现由他人提出的同维 4 档完整方案，但回答者明确拒绝采纳并再次确认执行 0 档行为，用于检查归属、否定和最终行动，而不能按孤立关键词升档。噪声模板把同一等级的证据以口语、省略和跨字段形式表达。构造等级在任何预测前由量规模板确定，模板变体不读取任何方法预测。

正式参考建立顺序为：

1. 使用另行冻结的 0—4 行为量规；
2. 三轮合成独立判断使用相互隔离的随机流，并以冻结构造等级、案例类型和三种角色关注点的预设误差模型生成；各轮不读取其他轮次或方法预测；
3. 保存全部原始标签，不覆盖分歧；
4. 任一轮次间分歧，或三轮一致但与冻结构造标准冲突的案例，均进入单独裁决记录；
5. 裁决只依据量规和文本行为证据，不读取方法预测；
6. `ecd_reference_labels.csv` 保存最终参考。

这些轮次是围绕构造标准生成的合成独立判断，不是真实专家标注，也不是三个实际 LLM 或人员调用。`annotation_agreement.json` 保存一致性结果，供报告时如实表述。

## 10. 防止标签泄漏

- 方法输入优先读取不含真值的 split 轨迹包、事件表和评分表；
- `ability_truth_long.csv`、`event_score_truth_long.csv`、`facet_truth.csv` 只用于评价；
- `trajectory_observations.csv` 为便于统一分析包含揭盲真值列，拟合代码必须显式排除所有 `*_true`、`reference_score` 和外部真值；
- ECD 编码器只读取情境、四个回答字段、五维量规和固定行动白名单；`target_dimension` 仅在预测保存后用于抽取焦点维度指标，`constructed_reference_score`、各轮标注和 `ecd_reference_labels.csv` 均不发送给编码器；
- 60 条开发材料只写入独立开发预测目录；正式 300 条在提示、候选切分、模型、参数和重试预算冻结后另行运行；
- 标注资产中的 `prediction_visible=0` 记录了标注阶段未读取方法输出。

## 11. 复现

从工作区根目录运行：

```bash
python method_validation/data/generate_synthetic_data.py
```

脚本只依赖 Python 标准库。它验证蓝图库版本，然后使用稳定 SHA-256 子随机流完整重写生成资产，并检查 ECD 开发/正式分区的规模、平衡、ID 唯一性和内容不重合。`freeze_manifest.json` 保存每个资产的字节数、记录数和 SHA-256；`freeze_manifest.sha256` 保存清单本身的哈希。

## 12. 适用范围与限制

该生成过程有意设置了共锚动态多面模型要处理的蓝图、形式、状态、评分者和版本效应，因此适合展示方法在理想且合理目标条件下的参数恢复与相对优势。它并不证明这些参数分布与真实创业课程相同，也不替代真实文本、真实专家和外部迁移案例验证。当前每人仅五个锚；每事件三个证据维属于理想且合理的多证据蓝图条件，不表示任意文本都能稳定支持三个维度。末周、周级或总体能力及群体/面参数应优先于过度精细的逐轮个体解释，未来真实数据仍需检验次级证据是否具有足够内容效度与评分可靠性。
