Methodology and Transparency

What the system does, and clearly what it cannot do

VentureBridge is an entrepreneurial teaching and process recording system awaiting further experimental validation. The LLM API is used for profile structuring, direction recommendation, main storyline event narration, mapping open decisions to whitelist actions, ECD process evidence encoding, and reflective feedback; an external rule engine independently calculates and saves numerical states, and the LLM has no authority to directly modify these values.

01 · Processing Workflow

From Input to Continuous Simulation

  1. Input

    Minimized Data

    Learners actively fill in background, experience, skills, interests, resources, constraints, and entrepreneurial experience, and remove identity information before submission.

  2. Profile

    Structured Draft with Evidence

    The LLM API extracts summaries, source snippets, confidence levels, and conflicts. Learners must be able to view and correct them.

  3. Recommendation

    2–3 Learning Hypotheses

    The system explains the basis for direction, uncertainty, and practice focus; recommendations can be questioned, rejected, and resubmitted.

  4. Simulation

    Rule State + Constrained Narration

    The LLM generates main storyline event narration based on the blueprint and visible state, maps open answers to whitelist actions, extracts process evidence, and generates reflective feedback; only the explicit rule engine is responsible for updating numerical resources.

02 · Learner Profile

Profiles are editable; MBTI is merely a weak cue

A profile is not a fixed personality label. The system should associate learner original text with extraction results, mark uncertainty, and retain corrected new versions. Recommendations must not be driven solely by a single personality type.

System Can

Summarize submitted experiences, interests, resources, and constraints, and point out contradictions or gaps in materials.

System Should Not

Assert real-world career fit, entrepreneurial potential, personality truth, or success probability based on MBTI or a single experience.

03 · Continuous Simulation

LLM Writes Narration, Rules Determine State Transitions

Numerical values such as cash, team, product, market evidence, reputation, and compliance are saved in an external state machine. Events can only reference allowed display states; after learners submit actions, the rule table calculates main storyline changes. LLM output must pass structural validation and cannot directly rewrite database values.

Open answers are first mapped by the LLM to one action code allowed by the current blueprint, while recording the model's self-reported classification confidence, mapping uncertainty, and alternative codes. Mapping may still fail; these values are uncalibrated, not correctness probabilities, and cannot turn rule state changes into real-world result predictions.

This improves trajectory auditability, but does not mean generated events equate to the real market. Event consequences are conventions within the teaching model, not business predictions.

04 · Shared Anchor Bridging

Briefly Enter Common States Within Personalized Mainlines

Predefined checkpoints use an auditable scheduler to deploy "Boardroom Stress Tests" at overlapping learner and time points. Anchor events run in isolated states, restoring the learner's mainline prior to entry upon completion.

Precise Common Version
Fixed state blueprints, information, and target evidence, used to maintain common tasks required for scale linkage.
Industry Surface Version
Maintain capability requirements and blueprints, only randomly changing industry surface contexts to preserve data for later testing of surface form differences.
Deployment Records
Save blueprints, forms, deployment probabilities, mainline path states, prompts, and model versions.
Important: Anchors Are Not Automatically Validated Scales

Only if subsequent methodological experiments support equivalence, common support, and link stability can they be used for cross-path comparison. The current implementation is only responsible for correct deployment and recording, not claiming verification.

The LLM can extract textual evidence according to explicit rubrics, but automatic coding may still drift, misjudge, or be influenced by phrasing. This system retains model, API, and prompt versions; their consistency, validity, and fairness belong to subsequent experiments and are not concluded in the current implementation.

06 · Data and API

Minimized, Traceable, Deletable

  • API keys are read only from server environment variables, not entering web pages, prompts, or application logs.
  • Send minimized data required to complete current functions to model services, using de-identified aliases.
  • Record call purpose, model and prompt versions, parameters, status, duration, input summary hash, and structurally validated model outputs to support troubleshooting and auditing.
  • Learners can check and correct profiles, and delete local learning spaces and associated records.

Specific deployments still require ethical and data protection reviews based on the institution, API provider terms, and applicable laws. Code-level controls cannot replace institutional responsibility.

07 · Known Limitations

When to Stop Relying on the System

  • Unreliable Facts or Rules: If events cite non-existent regulations, prices, or real-world entities, stop the current task and verify with the instructor.
  • State Contradictions: If narration conflicts with page values, use explicit state as the record basis and report the issue.
  • High-Risk Real Decisions: Financing, contracts, legal, medical, safety, or real employment decisions must seek qualified professional advice.
  • Over-reliance: The system should promote evidence gathering and reflection, not replace autonomous judgment, field interviews, or team discussions.

Meaning of Current Deliverables

This is a runnable and verifiable implementation of a methodology and teaching system. It has not executed methodological validation or educational application experiments, and cannot claim measurement validity, superiority over baselines, or improved learner capabilities based on this.
